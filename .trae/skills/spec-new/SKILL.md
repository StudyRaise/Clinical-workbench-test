# 生成功能规格文档

## 前置检查
1. 读取 `AGENTS.md` 的文档索引，确认是否已有相关模块文档
2. 如果 `docs/features/` 下已有同名模块，先读它，做增量更新而非重建
3. 如果只是改个变量名、修个明显 bug（1-2 文件、半天内），**不要用本技能**，直接做

## 生成步骤
按以下顺序与我确认，不要一次性全问：
1. **要解决什么问题** — 一句话。如果我说不清楚，帮我问到清楚为止
2. **需求清单** — 拆成可勾选的条目
3. **接口设计** — 方法、路径、作用（注意本项目三层边界：web → BFF → inference，标注改动落在哪一层）
4. **数据模型** — 涉及哪些 entity（packages/db），是否需要新增字段
5. **边界 Case** — 这里是重点，帮我穷举：并发、超时、重复调用、数据不一致；本项目额外穷举：跨租户越权、PHI 泄漏路径、审计留痕
6. **依赖与被调用** — 上下游模块
7. **验收标准** — 可勾选的测试点
8. **Out of Scope** — 明确不做什么

## 输出
写入 `docs/features/<module>.md`，frontmatter 包含：
```
module, status: planning, updated: <今天>, owner
```

## 注意
- 文档写"意图和约束"，不写"实现细节"——函数签名会变，抄进来两周就误导人
- 边界 Case 这一节宁可多花时间，这是文档最大的价值所在
- 涉及 PHI、多租户、审计的设计点必须在文档里显式说明
- 生成后让我 review，**我确认后才开始写代码**
