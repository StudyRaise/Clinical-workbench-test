# 回写功能文档

## 步骤
1. 找到本次改动触及的模块，读 `docs/features/<module>.md`（没有就跳过，不强行补写）
2. 用 `git diff` 看实际改了什么
3. 逐节比对，更新以下内容：
   - frontmatter 的 `status` 和 `updated`
   - 需求清单里已完成的条目打勾
   - 接口设计：实际签名与文档不符的，**以代码为准更新文档**
   - 验收标准：已验证的打勾
   - 新增的边界 Case（实现过程中才发现的，尤其是租户/PHI/审计相关的）
4. **压缩**过程性内容：调试中的试错、被否决的中间方案，不要留在文档里
5. 如果本次实现推翻了某个已有决策，提醒我新建一条 ADR，不要直接改旧 ADR

## 铁律
- 文档是给"下一轮会话的 AI"读的，不是给现在的我读的
- 保持精简。一份功能文档超过 200 行说明该拆分模块了
- 如果实现方式与设计文档有偏差，先问我是"改文档"还是"改代码"
