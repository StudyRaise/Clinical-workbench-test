# 记录架构决策

在 `docs/adr/` 下新建 `<序号>-<决策主题>.md`，序号递增（先看目录里现有最大序号）。

## 必填内容
- 背景：为什么需要做这个决策
- 结论：选了什么
- 理由：为什么（数据量级、团队能力、运维成本、合规要求等具体依据）
- **否决的方案 + 否决原因**（这一节最重要，防止 AI 以后重新提议）
- 何时重新评估：给出触发条件

## 本项目常见的应记决策
- LLM provider 选型与切换
- 检索策略的选择（Hybrid / Graph RAG / Timeline / Schema-aware）
- 安全合规设计（脱敏粒度、加密范围、审计保留期、租户隔离方式）
- 数据存储选型（MySQL / Milvus / MinIO / Redis 的用途边界）

## 不值得记的
- 只有唯一合理选项的
- 纯实现细节（用 for 还是 forEach）
