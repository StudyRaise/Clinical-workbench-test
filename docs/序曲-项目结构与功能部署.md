# 临床 AI 工作台 · 项目结构与功能序曲

> 本文档是项目“序曲”：用一页看清它是什么、怎么组织、有哪些功能，以及如何一键跑起来——从本机到线上。

---

## 1. 项目一览

**临床 AI 工作台（Clinical AI Workbench）** 是一个面向医院/科研机构的多租户 AI SaaS 平台，基于 RAG（检索增强生成）把三类高频、重复性强的临床文书工作统一到一个产品里：

| 模块 | 业务价值 | 核心检索策略 |
|------|---------|-------------|
| **术前谈话分析**（`/preop`） | 校验谈话记录法定告知要素完整性，输出缺失项/风险点/患者疑问清单 | Hybrid Search（向量 + BM25） |
| **出院随访总结**（`/discharge`） | 自动生成患者版通俗出院指导 + 医生版随访计划 | Timeline 感知检索 + Graph RAG |
| **科研数据清洗**（`/research`） | 从批量 PDF/Word/OCR 报告抽取结构化字段，附置信度与来源引用 | Schema-aware Retrieval + 术语标准化 |

平台同时提供**知识库管理**（文档摄取 -> 分块 -> 向量化 -> 检索）与**安全合规底座**（多租户硬隔离、审计日志、PHI 脱敏、字段级加密、RBAC 权限），并以**国产大模型 API**（SenseNova 商汤日日新 `glm-5.2`，兼容通义千问 / DeepSeek）作为推理后端。

│  推理服务 apps/inference  (FastAPI · LangChain · RAG)        │   :8000/8001
│  · LLM/Embedding 客户端 · 脱敏中间件 · 多策略检索 · 异步摄取   │
└───────┬───────────┬────────────┬─────────────┬──────────────┘
        │           │            │             │
   ┌────▼───┐  ┌────▼────┐  ┌────▼───┐  ┌──────▼──────┐
   │ MySQL  │  │ Milvus  │  │ MinIO  │  │ Redis/Celery│
   │ 业务数据│  │ 向量库   │  │ 对象存储│  │ 异步队列     │
   └────────┘  └─────────┘  └────────┘  └─────────────┘
   共享包 packages/*（prompts/llm-clients/rag/guardrails/costs/db...）

三层职责边界清晰：**Web 只做展示与交互，BFF 管业务/权限/合规，Inference 管 AI 与检索**。前端不直连数据库，PHI 不直达云端 LLM（先经脱敏中间件）。

## 4. 功能模块与能力清单

### 4.1 三大业务模块（经 BFF 转发到 Inference）

| 路由 | 入参 | 出参 | 检索/生成链路 |
|------|------|------|--------------|
| `POST /api/preop/analyze` | 谈话文本 | 手术名、风险、替代方案、缺失项、完整性评分 | 脱敏 -> Hybrid Search -> LLM 抽取 -> 规则引擎校验 |
| `POST /api/discharge/summarize` | 出院小结/病程/医嘱文本 | 患者版指导、医生版随访计划、随访日期 | 脱敏 -> Timeline 检索 -> Graph RAG -> LLM 生成 |
| `POST /api/research/clean` | 文本数组 | 结构化字段表（字段/值/置信度） | 脱敏 -> Schema-aware 检索 -> 术语标准化 -> LLM 抽取 |

### 4.2 RAG 引擎与知识库

- **文档摄取**：PDF/Word/TXT/扫描件（OCR）-> 分块 -> Embedding 向量化 -> 存 Milvus，原文存 MinIO；批量摄取走 **Celery 异步队列**不阻塞主流程。
- **多策略检索**：Hybrid Search、Timeline 感知、Graph RAG、Schema-aware Retrieval。
- **知识库接口**：`POST /api/knowledge/documents`（上传）、`/ingest`（异步摄取）等。

### 4.3 安全合规底座

- **认证与 RBAC**：JWT + 五角色（admin/doctor/nurse/researcher/patient），`@Roles()` 守卫。
- **多租户硬隔离**：ORM 层自动注入 `facility_id` 过滤，跨租户返回空集。
- **审计日志**：who/when/what/from where，追加写不可篡改，保留 6 年（`/api/audit-logs`）。
- **PHI 脱敏**：调用云端 LLM 前识别替换敏感字段，本地加密保留映射表，返回时还原。
- **字段级加密**：AES-256-GCM，应用层执行。
- **合规护栏**：越狱提示/敏感词拦截。
- **Token 成本追踪**：用量/预算告警。

### 4.4 开放接口一览（BFF，前缀 `/api`）

```
GET  /health                        健康检查
POST /auth/register  /auth/login    注册 / 登录（JWT）
POST /preop/analyze                 术前谈话分析
POST /discharge/summarize           出院随访总结
POST /research/clean                科研数据清洗
POST /knowledge/documents[/ingest]  知识库上传 / 摄取
GET  /users   /users/me             用户列表 / 当前用户
GET  /audit-logs                    审计日志（admin）
POST /inference/completions         LLM 补全
GET  /docs                          Swagger API 文档
```

Inference 侧还暴露 `/health`、`/v1/completions`、`/v1/embeddings`。

## 6. 环境变量（`.env`）

首次运行由脚本自动从 `.env.example` 生成 `.env`。**生产环境必须修改**以下项：

| 变量 | 说明 | 必改（生产） |
|------|------|:---:|
| `JWT_SECRET` | JWT 签名密钥（强随机串） | ✔ |
| `FIELD_ENCRYPTION_KEY` | 字段加密 32 字节密钥 | ✔ |
| `LLM_PROVIDER` | 模型服务商：`sensenova`（默认）/ `qwen` / `deepseek` | |
| `SENSENOVA_API_KEY` / `SENSENOVA_BASE_URL` / `SENSENOVA_MODEL` | SenseNova 商汤日日新 Key / 端点 / 模型（默认 `glm-5.2`） | ✔ |
| `QWEN_API_KEY` / `DEEPSEEK_API_KEY` / `EMBEDDING_API_KEY` | 通义千问 / DeepSeek / Embedding API Key | 按需 |
| `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | 全局覆盖（可选），设置后优先于上方 provider 配置 | 可选 |
| `DB_PASSWORD` | MySQL 密码 | ✔ |
| `CORS_ORIGIN` | 允许跨域的前端来源（逗号分隔） | 线上 ✔ |
| `NEXT_PUBLIC_API_BASE` | 前端访问 BFF 的地址（Docker 构建期注入） | 线上 ✔ |
| `INFERENCE_URL` | BFF 转发推理服务地址 | 本地默认 |
| `NEXTAUTH_SECRET` / `NEXTAUTH_URL` | 认证配置 | ✔ |

> 提示：`openssl rand -hex 32` 可生成安全随机串。

## 7. 部署流程

### 7.1 前置依赖

- **本地开发**：Node.js 18+、pnpm ≥ 8.15、Python 3.11+、Docker（含 Compose v2）
- **线上服务器**：Linux（Ubuntu/Debian/CentOS）+ Docker + Compose v2，开放端口（默认 3000/3001；建议仅对公网暴露 3000，API 经反向代理转发）

### 7.2 方式一：本地开发部署（Windows）

双击 `scripts\start.bat`，脚本自动完成：

1. 生成 `.env`（若不存在）
2. `docker compose -f infra/compose/compose.dev.yml up -d` 启动基础设施
3. `pnpm install` 安装前端/BFF 依赖
4. 创建 `apps/inference/.venv` 并安装 Python 依赖
5. 分别弹出 **Web / BFF / Inference** 三个服务窗口

停止：直接关闭三个服务窗口，运行 `scripts\stop.bat` 停基础设施（数据卷保留）。

### 7.3 方式二：本地开发部署（Linux / macOS）

```bash
chmod +x scripts/start.sh
./scripts/start.sh dev        # 阻塞前台运行，Ctrl+C 一并停止三服务
./scripts/start.sh stop dev   # 停止基础设施
```

### 7.4 方式三：线上部署（Docker Compose 全量，一键）

```bash
# 1. 拉取代码后进入仓库根目录
# 2. 准备环境变量（务必修改密钥 / API Key / 域名）
cp .env.example .env && vim .env

# 3. 一键构建并后台启动（等价于 docker compose -f infra/compose/compose.prod.yml up -d --build）
./scripts/start.sh prod

# 4. 常用运维
./scripts/start.sh status     # 查看容器状态
./scripts/start.sh logs web   # 跟踪某服务日志
./scripts/start.sh stop prod  # 停止线上服务（保留数据卷）
```

`compose.prod.yml` 一次编排全部服务：`mysql / redis / etcd / minio / milvus / inference / celery-worker / api / web`，服务间以服务名互访（不受 `.env` 中 localhost 影响），MySQL/Redis/Milvus 均带健康检查，应用在其就绪后才启动。上线后访问：

- Web：`http://<服务器IP>:3000`
- API：`http://<服务器IP>:3001/api`
- Swagger：`http://<服务器IP>:3001/api/docs`

### 7.5 线上部署进阶（生产加固，推荐）

1. **反向代理 + HTTPS**：用 Nginx/Caddy 将 `域名 -> :3000`，`api.域名 -> :3001`，终止 TLS（1.2+）。示例：

```nginx
# /etc/nginx/conf.d/workbench.conf
server {
    listen 80;
    server_name workbench.example.com api.example.com;

    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
    }
}
```

2. **同步修改 `.env`**：`NEXT_PUBLIC_API_BASE=https://api.example.com/api`、`CORS_ORIGIN=https://workbench.example.com`，重新 `./scripts/start.sh prod`（重建 Web 镜像注入新地址）。
3. **安全建议**：改用强密钥与独立数据库账号；`FIELD_ENCRYPTION_KEY` 用密钥管理服务托管；对公网仅暴露 443/80；开启防火墙并定期备份 `mysql-data`/`minio-data` 等数据卷；生产建议关闭 `synchronize` 改用迁移。
4. **GPU 推理（可选）**：如需本地部署模型，参考 `infra/compose/compose.gpu.yml` + `Dockerfile.inference.gpu`。

## 10. 常见问题（FAQ）

- **`localhost` 无法访问推理服务？** Node 18 的 fetch 会把 `localhost` 解析到 IPv6 `::1`，请在 `.env` 使用 `INFERENCE_URL=http://127.0.0.1:8000`。
- **API 返回 `degraded`？** 说明 BFF 未能连通推理服务或推理依赖（MySQL/Milvus/MinIO/LLM Key）未就绪，属降级保护，按序检查上述服务与 API Key。
- **前端接口报跨域？** 本地检查 `CORS_ORIGIN` 是否包含当前前端地址；线上确认反向代理后域名已加入 `CORS_ORIGIN`。
- **线上访问仍指向 localhost？** 修改 `NEXT_PUBLIC_API_BASE` 后必须**重建** Web 镜像（`./scripts/start.sh prod` 会自动 `--build`）。
- **数据库表未自动创建？** BFF 默认 `synchronize: true` 自动建表；如已关闭，请先执行 TypeORM 迁移。
- **批量文档摄取未执行？** 确认 `celery-worker` 容器运行、`REDIS_URL` 指向可用的 Redis。
